This exists so we **stop guessing** at the JobTread API. It is generated by walking the live
schema through the MCP connector `mcp__claude_ai_JobTread_x_Ascent__query` (the raw
`api.jobtread.com/pave` endpoint does **not** support introspection — only that tool does).

- **Provenance:** everything here is **[schema]-level** — it describes what fields/types/mutations
  *exist* and their *shapes/types*, straight from introspection. It does **not** encode runtime
  *behavior* (tax carves, silent divides, whole-array replaces, UTC quirks). Those are in the
  **jt-pave-api-reference** memory, the inline "confirmed live" JSDoc in

  rules in `JobTread.js`. Per CLAUDE.md rule #3: trust the schema for **reads**; a **write** of a
  new field still needs a live probe to confirm behavior.
- **Authoritative source:** if this file and live introspection ever disagree, **introspection
  wins** — re-run the recipe below. This is a snapshot; the schema is a living thing.
- **Status:** **all six domains walked from the live schema on 2026-07-30** — Grants/Org/Accounts,
  Jobs/Budget, Documents/Payments, Tasks/Schedule/Time, Custom Fields/Files, and

## Fundamentals

### Endpoint & auth
- **One endpoint:** `POST https://api.jobtread.com/pave`, `Content-Type: application/json`. Every
  read **and** write goes through this single URL — no REST paths, no per-entity endpoints.
- **Auth is the `grantKey`**, passed inside the top-level `$` args of the query body — there is no
  `Authorization` header. **The grant key is a server-side secret; never ship it to a browser.**
  ```json
  { "query": { "$": { "grantKey": "<KEY>" }, "<rootField>": { "$": { ...args }, "<subField>": {} } } }
  ```
- **Root `$` options:** `grantKey`, `notify` (`false` suppresses notifications), `timeZone` (IANA
  tz for tz-aware data), `viaUserId` (scope an action to a user).
- **Errors** come back as `{ "errors": [{ "message": ... }] }` and must be checked **independently
  of HTTP status**. A bad key returns plain text (`Supplied key is invalid`).

### Query grammar (Pave = a JSON graph API, GraphQL-like)
- **Root object keys are root fields.** Both entity **reads** (`job`, `document`, `account`,
  `organization`, `currentGrant`, …) and **mutations** (`createDocument`, `updateJob`,
  `deleteCostItem`, …) live at the query root. Mutations are never nested under an entity.
- **Arguments go under the special `$` key.** Select a scalar with an empty object `{}`.
- **Field alias `_`:** alias any field to a schema type, or expose a typed connection under a
  custom name — e.g. `"scheduledTasks": { "_": "tasks", "$": { "where": ["isToDo", false] } }`,
  or a named aggregate `"priceSum": { "_": "sum", "$": "price" }`.
- **Inline array items carry a `_type` tag** (e.g. a `lineItems` entry is `{ "_type": "costItem", … }`).
- **Get org context:** `{ "currentGrant": { "organization": { "id": {} } } }`.

### The uniform **connection** shape (used by every list field below — defined once here)
- **Input:** `{ page, size, where, sortBy, group, with, expressions }`
- **Output:** `{ nodes, nextPage, previousPage, count, sum, avg, min, max, values, withValues }`
- Domain sections below only call out a connection's **non-standard** args (e.g. `files` adds
  `asZip`, `download`).

### Filtering, sorting, aggregation
- **`where` is an `expression` tree** (schema type `expression`), NOT a flat tuple. Each expression is a
  one-key object; the building blocks (confirmed by introspecting the `expression` type):
  - **Operands:** `{ "field": "<name>" }` or `{ "field": ["path","to","field"] }` (1–10 segments) ·
    `{ "value": <literal> }` for a constant · `{ "subfield": [<expr>, ["path"]] }`.
  - **Compare (binary `[lhs, rhs]`):** `=`, `!=`, `<`, `<=`, `>`, `>=`, `like`, `not like`.
  - **Sets / ranges:** `{ "in": [<expr>, [<expr>, …]] }`, `not in` · `{ "between": [<expr>, [lo, hi]] }`, `not between`.
  - **Logic:** `{ "and": [<expr>, …] }` · `{ "or": [<expr>, …] }` · `{ "!": <expr> }`.
  - **Also:** math (`+ - * / ^ round sqrt floor ceil min max coalesce`), `concat`, `if`, `cast`,
    `date`/`datetime` (`{startOf|endOf|fromNow}`), `formatDatetime`, `distance`.
  - **Example** — approved vendor bills:
    ```json
    { "and": [ { "=": [ { "field": "type" },   { "value": "vendorBill" } ] },
               { "=": [ { "field": "status" }, { "value": "approved" } ] } ] }
    ```
  *(The appscript/companion `pave()` clients pass a legacy array-tuple shorthand —
  `[["type","vendorBill"],["status","draft"]]` (implicit `=`, implicit `and`) — which the raw endpoint
  accepts, but the **MCP connector requires the explicit `expression` form above**. A bare 2-element
  clause is otherwise parsed as a field PATH, not `[field, value]`. Behavior: a `where` on `externalId`,
  or one joining on `document`, returns 400 — filter those client-side. See memory.)*
- **`sortBy`:** array of `{ field, order? }` (`order` = `asc`/`desc`) — confirmed live.
- **`group` / aggregates:** `group: { by: [<fields>], aggs: { <alias>: { sum: "<field>" }, <alias>: { count: [] } } }`
  paired with `withValues: {}`. A bare `count: {}` returns a count. This is how JT computes its own
  job financials server-side.

### Pagination & size limits
- **Cursor pagination:** request `nextPage: {}` in a connection; feed the returned opaque token
  back as the `page` arg on the next call. **`offset` throws 400 — cursor paging is mandatory.**
- **Page-size cap is 100.** `size: 250` **silently returns 0 nodes** — never exceed 100.
- **413 two-phase rule:** `costItems` / `referencedDocuments` nested inside a *paged* `documents`
  connection return HTTP 413 at size 100 — drop those to `size: 25`/`50`, or read the **flat**
  `job.costItems` connection and join to documents client-side by document id.

### Mutation return convention
- **`create*`** exposes a sibling read-back node on `root`: `createdDocument`, `createdJob`,
  `createdCostItem`, `createdFile`, `createdTimeEntry`, `createdUploadRequest`, … (each nullable,
  typed as the entity). Select fields off it in the same call.
- **`update*` / `delete*` / action mutations** return the **bare `root`** (there is no
  `updatedX`/`deletedX` node) — re-read the record via its getter or a parent connection.
- **`oneOf` inputs** expose their branches as `_on_<variant>` in introspection paths.

### Introspection recipe (the "stop guessing" workflow — via the MCP tool)
1. **Root fields:** `{"schema":{"$":{"path":"root"}}}`
2. **Keyword search anywhere in the tree:** `{"schema":{"$":{"path":"root","search":"<kw>"}}}`
3. **Expand a field or type:** `{"schema":{"$":{"expand":true,"path":"<path>"}}}`
   - Global types by **name**: `path:"job"`, `path:"document"`.
   - A root read field resolves to `{ input:{id}, type:<namedType> }` — expand the named type for
     its fields.
   - Path rules: object key → `.key`; input → `.$`; oneOf variant → `._on_<key>`. Example:
     `root.createDocument.$.lineItems`, `root.pdf.$._on_budget`.
4. **Execute** the read/mutation.

### Scalar type vocabulary
`string`, `number`, `int`, `boolean`, `date`, `datetime`, `time`, `jobtreadId` (id string), `url`,
`emailAddress`, `phoneNumber`, `color` (`#rrggbb`), `path` (signature path), plus `nullable`
wrappers (written `type?` below) and enum/global types (`documentType`, `jobPriceType`, …).

#### `commentFile` (read) — root: `commentFile(id)` — file attached to a comment (managed via the comment mutations' `files` array)
- **Scalars:** `id` jobtreadId · `createdAt` datetime · `name` string · `type` string (MIME) · `size` int ·
  `storageId` jobtreadId · `url` url? (**input** `{download, original, size}`) · `annotations` object[]?.
- **References:** `comment → comment`, `file → file?`.

### Mutations
- **`createCustomField`** → `createdCustomField`: `organizationId`, `name` (≤128), `type` customFieldType,
  `targetType` customFieldTargetType, `minValuesRequired` (≥0), `maxValuesAllowed?` (≥1), `options?` (1–100,
  for `type: option`), `defaultValue?`, `positionAfterCustomFieldId?`, `showOnSpecifications` (def false).
- **`updateCustomField`** → `root`: `id` (req); opt `name` (≤128), `minValuesRequired` (≥0), `maxValuesAllowed?`
  (≥1), `defaultValue?`, `positionAfterCustomFieldId?`, `showOnSpecifications`, and **`options`** — array of
  oneOf `_on_string` (plain string) | `_on_rename` (`{from, to}` to rename an option in place), 1–100.
- **`deleteCustomField`** → `root`: `id`.
- **`createCustomFieldMapping`** / **`deleteCustomFieldMapping`** → `root`: `name`, `customFieldId`, `targetType`
  customFieldTargetType. (No readable `customFieldMapping` type.)
- **`createFile`** → `createdFile` (step 3 of upload — attach an uploaded `uploadRequest`, copy a file, or pull
  a public URL sourced at `createUploadRequest`): `targetId`, `targetType` fileTargetType (`dailyLog`, `document`,
  `task`, `job`, `location`, `contact`, `account`, `organization`), `name`, `uploadRequestId?`,
  `annotatedUploadRequestId?`, `copyFromFileId?`, `copyFromFile {_type, id}?`, `fileTagIds` (≤10, def []),
  `folder?`, `description?`.
- **`updateFile`** → `root`: `id` (req); opt `name`, `description?`, `folder?`, `fileTagIds` (≤10),
  `annotatedUploadRequestId?`.
- **`deleteFile`** → `root`: `id`.
- **`createFileTag`** → `createdFileTag`: `organizationId`, `name` (≤25), `color`, `description?` (≤256).
- **`updateFileTag`** → `root`: `id` (req); opt `name` (≤25), `description?` (≤256), `color`.
- **`deleteFileTag`** → `root`: `id`.
- **`updateLineItemFile`** → `root`: `id` (req); opt `name`, `annotatedUploadRequestId?`. (No create/delete root fields.)
- **`createUploadRequest`** → `createdUploadRequest` (step 1 of upload): `organizationId?`, `size?` (>0),
  `type?` oneOf `_on_string` (MIME like `image/jpeg`) | `_on_fromName` (`{fromName}` infers from a filename),
  `url?` (source from a public URL instead of uploading bytes), `annotations?` (≤1000; oneOf `_on_path`/`_on_text`/
  `_on_point`/`_on_meta` markup objects), `captchaToken?`, `webFormKey?`.
- **`updateUploadRequest`** → `root`: `id` (req); opt `annotatedUploadRequestId?`.
- **`renameFolder`** → `root`: `jobId`, `oldName`, `newName` (renames a virtual folder in a job's file tree).
- **`createComment`** → `createdComment`: `message` (≤4096, req), `targetId?`, `targetType?` (`file`, `dailyLog`,
  `timeEntry`, `task`, `document`, `job`, `account`, `organization`, `comment`), `name?` (≤128),
  `parentCommentId?`, `isReply` (def false — posts a reaction/like, use an emoji as `message`), `isPinned`
  (def false), `isVisibleToAll?`, `isVisibleToCustomerRoles?`, `isVisibleToInternalRoles?`,
  `isVisibleToVendorRoles?`, `assignees` (≤100; oneOf `_on_role`/`_on_membership`/`_on_user`), `files` (≤10;
  oneOf `_on_new {name, uploadRequestId}` / `_on_existing {_type, id, name, annotatedUploadRequestId}`).
- **`updateComment`** → `root`: `id` (req); opt `message` (≤4096), `name?` (≤128), `isPinned`, visibility flags,
  `files` (same oneOf, ≤10).
- **`deleteComment`** → `root`: `id`, `preserveChildren` (def false).
- **`updateCommentFile`** → `root`: `id` (req); opt `name`, `annotatedUploadRequestId?`.
- **`markCommentAsUnread`** → `root`: `id`.

**Notes:** `defaultValue`/`value` (custom fields) are polymorphic scalars — the effective type is dictated by
the field's `customFieldType`. `annotations` read back as untyped `object[]`; the writable annotation shape is
enumerated only on `createUploadRequest.annotations` (path/text/point/meta variants). Only `create*` mutations
expose a `created<X>` node; all others return bare `root`.
